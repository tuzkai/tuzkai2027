# Deploy TuzakAI on Render

This repository is a pnpm monorepo. Keep `pnpm-workspace.yaml`, the root
`pnpm-lock.yaml`, and all workspace directories together at the repository
root. Do not move the API manifest out of `artifacts/api-server/package.json`.
The workspace's `minimumReleaseAge: 1440` setting is intentional and is kept.

## What the Render Blueprint does

`render.yaml` creates one Node web service. Its build runs the workspace
typecheck, builds the TuzakAI storefront and jewelry designer, places the
designer under `/tuzakai/`, and builds the API server. In production, the API
serves the compiled storefronts and handles same-origin `/api` requests.

## Build and start commands

From the repository root:

```sh
corepack enable
pnpm install --frozen-lockfile
sh scripts/render-build.sh
pnpm --filter @workspace/api-server run start
```

The Render Blueprint runs the install and build commands for you. Render sets
`PORT` at runtime; do not hardcode it in the service settings.

## Required Render environment

Set these values in Render when creating the Blueprint:

- `DATABASE_URL`: PostgreSQL connection string reachable from Render. A
  Replit database is not automatically copied or reachable from this archive.
- `CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`: Clerk keys for the auth
  instance configured for this deployment.
- `VITE_CLERK_PUBLISHABLE_KEY`: the matching publishable key, available to the
  frontend build.
- `TUZAKAI_ADMIN_USER_IDS`: comma-separated Clerk user IDs explicitly
  authorized as administrators. Leaving it unset grants no administrator
  access; do not use a password or promote the first visitor.
- `SESSION_SECRET` is generated by the Blueprint.

Never put secret values in this file or in the ZIP.

## Existing Replit integrations

The archive contains application code and package configuration, not Replit
secrets, database contents, or integration credentials. Replit-managed
OpenAI/Whop integrations do not automatically become Render integrations.
Configure equivalent provider access separately before relying on those
features in a Render deployment. This Blueprint does not enable paid checkout
or grant purchase/download access.

## Deploying the ZIP

Use the ZIP as a source bundle: extract it and push the resulting repository
contents to a Git provider, then create a Render Blueprint from that repository.
Keep `render.yaml` at the repository root. Render needs the source repository
to build and track future changes; the ZIP itself does not contain runtime
secrets or an exported database.
